# KlimaEco — комплект развёртывания

> Это комплект запуска **текущего Anvil-приложения**, а не миграция на другой backend. Каталог, админка, расчёты и авторизация остаются внутри Anvil Runtime. До публичного запуска отдельно проверьте базу данных, права пользователей, секреты и интеграции.

## Быстрый выбор площадки

| Площадка | Подходит для полного приложения? | Что важно |
|---|---|---|
| Windows / локальный сервер | Да, для тестирования и внутренней сети | Компьютер должен работать, доступ из интернета требует HTTPS и настройки сети |
| VPS с Linux | Да, рекомендуемый вариант | Можно запускать Anvil App Server постоянно и подключить домен/HTTPS |
| Beget: бесплатный shared-хостинг | Не как полноценный Anvil Runtime | Подходит для статических файлов/PHP-сайта, но ограничения shared-хостинга не подходят для запуска собственного Anvil App Server с базой и постоянно работающими процессами |
| Beget VPS или другой VPS с Docker | Да, при достаточных ресурсах | Используйте Docker-пакет из этого каталога либо установку Anvil App Server по официальной инструкции |
| Render / Railway / другие PaaS | Возможно, если доступен постоянный процесс и persistent disk | Бесплатные лимиты, сон приложения и диски меняются; проверьте условия перед запуском |
| GitHub Pages / обычный статический хостинг | Нет, только статическая оболочка | Не исполняет Python-сервер Anvil, не заменяет базу и административную систему |

Официальные документы:
- Anvil App Server: https://anvil.works/docs/how-to/app-server
- Руководство запуска: https://github.com/anvil-works/anvil-runtime/blob/master/doc/getting-started.md
- Бесплатный хостинг Beget и его ограничения: https://beget.com/ru/hosting/free и https://beget.com/ru/rulesfree

## 1. Запуск на Windows (самый быстрый способ)

1. Установите Python 3.11 или совместимую версию Python 3 и Java (Amazon Corretto 8+).
2. Скачайте/клонируйте репозиторий: `git clone https://github.com/klimatst/anviklimat.git KlimaEco`.
3. Откройте PowerShell в папке `KlimaEco`.
4. Запустите:
   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\deployment\windows\start-local.ps1
   ```
5. Откройте http://localhost:3030.

Если скрипт заблокирован или среда уже создана, выполните вручную:
```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install anvil-app-server -r requirements.txt
.\.venv\Scripts\anvil-app-server.exe --app . --data-dir .anvil-data
```

Данные локального App Server будут сохраняться в `.anvil-data`. Не удаляйте эту папку, если там есть нужная база. Для переноса на другой компьютер остановите сервер и сделайте резервную копию всей папки данных.

## 2. Docker: локально или на VPS

Требуется Docker Engine + Docker Compose. Из корня репозитория:
```bash
docker compose -f deployment/docker-compose.yml up --build -d
docker compose -f deployment/docker-compose.yml logs -f app
```
Откройте http://localhost:3030. Остановка: `docker compose -f deployment/docker-compose.yml down`. Данные хранятся в volume `klimaeco-data`.

Это стартовая конфигурация для проверки, а не подтверждение production-готовности. Сначала запустите и проверьте проект на тестовой базе. Перед публичным запуском настройте домен, HTTPS, бэкапы и ограничения доступа к панели администрирования.

### Публикация на VPS

1. Подготовьте VPS с Linux, доменом и Docker.
2. Разверните репозиторий и запустите compose.
3. Откройте нужные порты только по инструкции вашего провайдера. Не оставляйте административные/служебные порты открытыми всему интернету.
4. Для HTTPS следуйте актуальной инструкции Anvil App Server: https://github.com/anvil-works/anvil-runtime/blob/master/doc/getting-started.md#making-it-accessible-over-https. Не включайте одновременно два HTTPS-прокси без настройки портов.
5. Проверьте логин, роли, каталог, добавление/редактирование товара, расчёты, загрузку фото, импорт/экспорт и восстановление резервной копии.

## 3. Beget и аналоги

### Beget Free shared hosting
Не загружайте туда только папку проекта и не ожидайте, что Anvil запустится как обычный PHP-сайт. В текущем репозитории есть Anvil Forms, server modules, схема Data Tables и Python-зависимости. Для полноценной работы нужен Anvil App Server и его среда выполнения/хранилище. У бесплатного shared-хостинга есть лимиты процессов и ресурсов.

Что можно разместить на обычном shared-хостинге:
- отдельную статическую страницу/лендинг;
- документацию и установочные файлы;
- отдельный frontend только после специальной сборки/миграции.

Это **не** даст полноценную работу каталога и админки без backend.

### Практичные варианты
- Beget VPS / другой VPS с Linux: наиболее прямой путь сохранить существующую Anvil-архитектуру.
- Anvil Cloud: наименьший объём инфраструктурной настройки, если устраивает модель хостинга Anvil.
- PaaS с постоянным процессом и диском: подходит после проверки доступности Docker/долгоживущего процесса, хранения данных и HTTPS.
- Полная миграция на Flask/FastAPI + PostgreSQL: отдельный проект разработки. Нельзя безопасно получить её простым копированием файлов — необходимо перенести таблицы, права, серверные функции, формы и тесты.

## 4. Секреты и безопасность

- Не коммитьте `.env`, API-ключи, пароли, приватные ключи и дампы с персональными данными.
- `.env.example` — пример, а не файл с реальными секретами.
- До открытия сайта в интернете проверьте, что все серверные функции проверяют права на сервере, а не только скрывают кнопки в UI.
- Настройте резервные копии каталога данных и проверьте восстановление.
- Используйте HTTPS, сильные пароли и ограничьте доступ к админке.
- Не импортируйте production-базу в тестовую среду без защиты персональных данных.

## 5. Android — самый быстрый путь

Самый быстрый вариант — сначала сделать сайт удобным на мобильном экране и PWA, затем обернуть его в Android-приложение через Trusted Web Activity (TWA). Это оболочка над размещённым сайтом, а не переписывание всей системы в Kotlin.

1. Сначала разверните приложение по HTTPS на собственном домене.
2. Проверьте мобильную навигацию, формы, фото, авторизацию, загрузки и работу каталога на телефоне.
3. Подготовьте web manifest и иконки. Файлы-шаблоны находятся в `deployment/pwa-template/`. Это шаблон, его ещё нужно подключить к фактическому HTML/маршрутам приложения.
4. Установите Node.js и Bubblewrap:
   ```bash
   npm install -g @bubblewrap/cli
   bubblewrap init --manifest https://ВАШ-ДОМЕН/manifest.webmanifest
   bubblewrap build
   ```
   Следуйте вопросам Bubblewrap, задайте уникальный application ID и название KlimaEco.
5. Для полноэкранной TWA создайте `/.well-known/assetlinks.json` на том же домене. В файл нужно внести package name и SHA-256 fingerprint **реального ключа подписи**. Без правильного файла Android может открыть сайт в обычной вкладке браузера.
6. Получите APK для внутреннего тестирования; для Google Play подготовьте AAB и настройте подпись приложения.
7. Протестируйте вход, выход, роли, загрузку файлов, внешние ссылки, отсутствие сети и обновления.

Официальное руководство Google: https://developer.android.com/develop/ui/views/layout/webapps/guide-trusted-web-activities-version2

### Важно про Android
PWA/TWA использует веб-приложение и требует доступного сайта. Если нужны полноценный офлайн-режим, push-уведомления, работа с Bluetooth/камерой или сложная фоновая синхронизация, объём разработки увеличится. Для максимального повторного использования сайта выбирайте PWA/TWA; для глубоких нативных функций — отдельное Android-приложение (Kotlin) или кроссплатформенный клиент (например, Flutter).

## 6. Чек-лист перед запуском

- [ ] Приложение запускается на тестовой среде.
- [ ] Схема Data Tables мигрировала без ошибок.
- [ ] Создан и проверен административный аккаунт.
- [ ] Проверены роли/права на сервере.
- [ ] Каталог: поиск, фильтры, карточка, цены, изображения, редактирование.
- [ ] Калькуляторы проверены контрольными инженерными примерами.
- [ ] Импорт/экспорт проверен на копии данных.
- [ ] Настроены HTTPS и домен.
- [ ] Настроены резервные копии и выполнено тестовое восстановление.
- [ ] На мобильном устройстве проверены все основные сценарии.
- [ ] APK/AAB подписан и проверен на реальном Android-устройстве.

## Что этот комплект делает сейчас

Он добавляет инструкции и стартовую Docker/Windows-конфигурацию для запуска **существующего Anvil-проекта**. Он не переносит Anvil в PHP и не превращает проект в нативный Android-клиент автоматически. После установки необходимо провести тест запуска и функциональные проверки на целевой площадке.
